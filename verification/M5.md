## Bundle inspection and optimization decision

Used the installed `next experimental-analyze --output`; no analyzer dependency/browser/package installation. [Compact module summary](m5-bundle-analysis.json) retains route/client boundaries. The analyzer runs its own experimental compile, not a deployable app build; its names/module-part sizes can differ from production chunks. Per-module raw/estimated compressed sizes are not network transfers. [Runtime capture](m5-performance.json) separately inventories 17 actual production chunk files and 14 public asset files, including gzip/Brotli estimates that are not assumed server compression choices.

Analyzer client JavaScript module parts from local src total 9,637 bytes for catalogue and 32,852 bytes for the entire course route including deferred dialogs and generated CSS-module mappings. Framework code dominates: React DOM client 200,702 raw bytes; the 112,594-byte nomodule polyfill is in the analyzer output but **not requested by this modern Chrome**. Neither fixture modules (`courses.ts`, worksheet/resource definitions) nor Axe/Playwright/ESLint authoring/test packages appear in client JavaScript. Relevant route content still travels in server HTML/RSC as intended.

Server header/material/seed-comment slots, minimal provider seeds, narrow subscriptions, native media and conditional dialog imports already avoid heavy initial work. Opening the first dialog loads the small shared dialog chunk once; subsequent PDF opening reuses it. Splitting every small dialog further or moving providers would add loading/state-lifetime complexity without a demonstrated benefit. No unused heavy dependency or oversized initially loaded asset was found. **No speculative runtime refactor or claimed before/after speedup**: preserve required behavior and desktop/mobile fidelity. Original fonts/photos remain the higher-priority fidelity gap.

## Reproduce

Build/start the app in one terminal; then:

```sh
node scripts/measure-production.mjs
node node_modules/next/dist/bin/next experimental-analyze --output
node scripts/summarize-bundle.mjs
```

Default reports are ignored local-*.json files; each script accepts an explicit output path for intentional milestone evidence. PERF_BASE_URL optionally selects the target. The analyzer decoder uses the inspected Next 16.3.8 internal format and fails on unsupported format; do not assume compatibility with every future Next version. Measurement records raw shifts, partial responses and a bounded playback wait. Earlier instrumentation captures are retained locally/ignored; the table above uses only the final capture. Raw local request timings/bytes vary with machine and browser scheduling. No timing threshold is asserted in functional tests.
