## Architecture and bounded acceptance

Pure transitions validate drafts/posts/exam IDs/options/indices and submitted scores; server route/static facts/seed comments remain server slots. Shared modal/form components and separate PDF/exam/question/leaderboard content keep responsibilities narrow. Dialog modules load on demand. No backend or server singleton; session here means the current in-memory app instance, not cross-reload storage.

An original one-page PDF (2205 bytes) and its real rendered page (102642 bytes) share the accessible JSON text. Regeneration script uses authoring tools outside runtime dependencies. PNG display plus zoom/text avoids native PDF plugin dependence; arbitrary PDF uploads/multi-document parsing are not implemented or required by the fixtures. Raster/PDF/media Git attributes preserve binary bytes.
